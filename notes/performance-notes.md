# パフォーマンスの学び

**結論: ボトルネックは常に「水滴の描画」だった。物理は安い。
計測なしの最適化は2回外した（推測は当てにならない）。**

## 計測基盤
- `#debug` でHUD（FPS / frame-ms avg・max / 粒数）＋**フェーズ別プロファイラ**
  （upd/mrg/bg/drw の指数移動平均ms）。これを入れて初めて犯人が特定できた。

## 実測（デスクトップ・豪雨飽和・360粒+ミスト~1900）
- upd 0.4 / mrg 0.4 / bg 0.1 / **drw 2.5** → 描画が7割。
- 対策後: drw ~0.6ms（中雨）。60fps安定、余裕大。

## 効いた最適化（効果順）
1. **ビーズスプライト**: r<5.5 の粒とミストは事前描画スプライトの drawImage 1発。
   クリップ+屈折+グラデ3枚 → 1 blit。（見た目統一のおまけ付き）
2. **静的オーバーレイの事前合成**: 毎フレームの createLinearGradient/RadialGradient
   （shine+vignette）を1枚のキャンバスに焼いて blit。グラデ生成は毎フレームやるな。
3. **mistCvs に触らない**: 吸収ゼロのフレームで destination-out を打つと
   GPUテクスチャ再アップロード（数ms級）。vol>0 のときだけ消去。
4. 屈折リング 4→3、ハイライトの save/scale/restore → ellipse fill。
5. グリッド近傍配列の再利用（毎フレームのGC/アロケーション排除）。
6. 探索範囲は自分サイズ基準（collision-design.md 参照）— 24ms スパイクの犯人だった。

## 予算
- 目標: フレームJS 8ms以内（ミドルスマホ≈デスクトップ×2〜3の余裕を見る）。
- 現在: 中雨 ~1.2ms / 豪雨 ~3.5ms（デスクトップ）。

## 未着手の伸びしろ
- 省電力モード（30fps化+雨条オフ）→ P4。
- WebGL 化すれば drw はGPUに移り、数千粒+真の屈折が可能（P3）。
- 内部解像度は CSS px のまま（DPR 1相当）。ユーザーからボケの指摘なし・軽さ優先で据え置き決定。
